You created `agent-0` and saw it reconciled into a pod. That pod is where the OpenClaw agent actually lives. To poke at the agent directly, you go **into the sandbox** — and a sandbox is just a gVisor pod, so "going in" is an ordinary `exec`.

## Confirm it's there

Agent pods live in the `openshell-sandboxes` namespace:

```bash
kubectl -n openshell-sandboxes get pods
```

You should see the pod backing `agent-0`, `Running`.

## Get a shell inside

The friendliest way is the fleet helper:

```bash-interactive
./scripts/fleet shell agent-0
```

That drops you into a shell **inside the sandbox**, on the other side of the gVisor boundary. Once you're in (the prompt changes to `sandbox@…`), try a few things:

```bash-ref
whoami
uname -a
ls /
```

<Callout type="note" title="Type these, don't Run them">
These only prove anything typed *inside* the sandbox prompt above — running them via Run/Shell from the lab shell would just show you the lab VM's own filesystem, not the sandbox's, and defeat the point.
</Callout>

You're running as a non-root user, inside runsc's user-space kernel — not the host. Type `exit` to come back out.

## The other doors

`fleet shell` is a convenience wrapper. Two equivalent ways to run a command inside the sandbox — the first is a genuine one-shot (safe to Run), the second opens another interactive prompt (Shell only):

```bash
openshell sandbox exec -n agent-0 -- whoami
```

```bash-interactive
kubectl -n openshell-sandboxes exec -it pod/default--agent-0 -- /bin/sh
```

A sandbox pod isn't behind a Deployment — the agent-sandbox controller reconciles the `Sandbox` CR straight into a pod, named `<workspace>--<sandbox-name>` (`default` is the CLI's default workspace, hence `default--agent-0`; confirm with `kubectl -n openshell-sandboxes get pods`). The `openshell` path goes through the gateway and the supervisor (so it respects the sandbox's identity and policy relay); the `kubectl exec` path goes straight at the pod. Both land you in the same container.

## Prove the isolation

From inside the sandbox, the agent's view of the world is deliberately small. The kernel it talks to is gVisor's, not the host's — that `uname` you ran reports the gVisor kernel. And the network is deny-by-default: the agent can reach `inference.local` (next lesson) and not much else.

<Callout type="lab" title="A sandbox is a pod, a pod is a sandbox">
There's no magic VM here — just a pod with a stricter runtime. That's the design: reuse everything Kubernetes already gives you (scheduling, RBAC, lifecycle), and add isolation + policy on top.
</Callout>
