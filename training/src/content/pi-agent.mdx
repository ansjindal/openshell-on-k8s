An **agent** is a model plus a **harness**: the program that sends your prompt to the model, runs the tools the model asks for, and feeds the results back until the model answers. In this lab you build one with **pi**, a small open-source harness, on your VM: connect it to the model, ask it something, then give it a shell and watch what it does with it.

  will="install the pi harness, connect it to your model API, and run it with and without a tool."
  time="about eight minutes."

<Section n="1" title="An agent on the VM" goal="Install pi, connect it to the model API and run it.">

<Step n="1" title="Install pi">

pi is an npm package. Install it into your home folder, so it needs no root:

```bash
npm install -g --prefix ~/.local --no-audit --no-fund @earendil-works/pi-coding-agent@1.5.2 && ~/.local/bin/pi --version
```
<Output summary="123 packages, and the pi CLI prints its version.">
<ExpectedOutput>
{`added 123 packages in 7s
1.5.2`}
</ExpectedOutput>
</Output>

</Step>

<Step n="2" title="Connect it to your model">

pi finds models in `~/.pi/agent/models.json`. Describe your model API there: the same `MODEL_BASE_URL` and `MODEL_NAME` the lab was set up with, and **a reference** to the key, `$MODEL_API_KEY`, which pi reads from the environment when it calls the model. The file never holds the key itself.

```bash
cd ~/openshell-on-k8s && set -a && . ./.env && set +a
mkdir -p ~/.pi/agent && cat > ~/.pi/agent/models.json <<EOF
{
  "providers": {
    "lab": {
      "baseUrl": "$MODEL_BASE_URL",
      "api": "openai-completions",
      "apiKey": "\$MODEL_API_KEY",
      "compat": { "supportsDeveloperRole": false, "supportsReasoningEffort": false },
      "models": [{ "id": "$MODEL_NAME" }]
    }
  }
}
EOF
PI_OFFLINE=1 ~/.local/bin/pi --list-models lab
```
<Output summary="pi lists one model on the provider you called lab: yours.">
<ExpectedOutput>
{`provider  model           context  max-out  thinking  images
lab       <MODEL_NAME>    128K     16.4K    no        no`}
</ExpectedOutput>
</Output>

`"api": "openai-completions"` means any OpenAI-compatible endpoint. `PI_OFFLINE=1` stops pi's own update check and install ping, so the only network calls are to your model.

</Step>

<Step n="3" title="Ask it something">

`-p` runs one prompt and prints the answer. `--no-session` keeps no history:

```bash
cd ~/openshell-on-k8s && set -a && . ./.env && set +a
PI_OFFLINE=1 ~/.local/bin/pi --provider lab --model "$MODEL_NAME" --no-session -p "In one sentence: what is an AI agent harness?" </dev/null
```
<Output summary="The model's answer, through pi.">
<ExpectedOutput>
{`An AI agent harness is a framework that provides an AI model with tools (like file reading, command execution, and code editing) and a controlled environment to perceive, act, and iterate on tasks such as software development.`}
</ExpectedOutput>
</Output>

(`</dev/null` tells pi there is no piped input to wait for.)

</Step>

<Step n="4" title="Give it a tool">

So far the model only talks. With `--tools bash`, pi lets the model run shell commands and reads it the results: now it is an agent. Ask it to reach a website:

```bash
cd ~/openshell-on-k8s && set -a && . ./.env && set +a
PI_OFFLINE=1 ~/.local/bin/pi --provider lab --model "$MODEL_NAME" --no-session --tools bash -p "Use bash to run curl -s -m 8 -o /dev/null -w %{http_code} https://example.com and reply with one line: the HTTP status it printed." </dev/null
```
<Output summary="200: the agent ran curl and reached example.com.">
<ExpectedOutput>
{`200`}
</ExpectedOutput>
</Output>

It worked, and that is the problem. On the VM the agent runs as you: it can reach **any** host, read **any** file you can, and its process holds your **real** model key in `MODEL_API_KEY`. Whatever a prompt talks it into, it can do.

</Step>

</Section>

## What you learned

<Learned next="/learn/agent-on-k8s" nextLabel="Deploy the agent on Kubernetes">

- **An agent is a model plus a harness.** pi sends prompts to the model, runs the tools it asks for, and feeds the results back.
- **The config holds a reference, not the key.** `$MODEL_API_KEY` is read from the environment when pi calls the model.
- **With a tool, the model acts.** On the VM the agent reached example.com, with your real key in its environment.

</Learned>
