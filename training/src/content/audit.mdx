Every decision a supervisor makes, every connection opened or refused, every HTTP request allowed or denied, every policy loaded, is written down as an **OCSF** event (the Open Cybersecurity Schema Framework). It's how you answer "what did this agent try to do?" after the fact.

## Signals and audit events

<ReadScene scene="obs" />

<ReadScene scene="ocsf" />


<Section n="1" title="Read audit events from the CLI">

Make an agent hit a few closed doors, then read each decision its supervisor wrote, straight from the CLI.

<Step n="1" title="Make some denied traffic">

Give the supervisor something to record: from `agent-0`, try one host its policy doesn't allow and one LiteLLM admin call its provider doesn't allow:

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -m 5 https://example.org >/dev/null; curl -s -X POST http://litellm.litellm.svc.cluster.local:4000/key/generate >/dev/null; echo done'
```


</Step>

<Step n="2" title="Read the OCSF events agent-0's supervisor wrote">

Every decision the supervisor made is an OCSF line in the sandbox's log. Read the latest ones:

```bash
openshell logs agent-0 -n 200 --source sandbox --since 5m | grep OCSF
```
<Output>
<ExpectedOutput>
{`[sandbox] [OCSF ] [ocsf] NET:REFUSE [MED] DENIED example.org [reason:policy_dns_ineligible]
[sandbox] [OCSF ] [ocsf] NET:OPEN [MED] DENIED /usr/bin/curl(0) -> example.org:443 [reason:transparent_tcp_policy_denied]
[sandbox] [OCSF ] [ocsf] HTTP:POST [MED] DENIED POST http://litellm.litellm.svc.cluster.local:4000/key/generate [policy:_provider_litellm engine:l7] [reason:L7_REQUEST deny POST ...]`}
</ExpectedOutput>
</Output>

How to read a line:

| Part | Meaning |
|---|---|
| `NET:OPEN`, `NET:REFUSE`, `HTTP:POST`, `CONFIG:PUBLISHED`, `SSH:OPEN` | event class and activity: a connection, a refused DNS name, an HTTP request, a policy load, an exec session |
| `ALLOWED` / `DENIED` | the decision |
| `/usr/bin/curl(0) -> example.org:443` | which binary tried to reach what |
| `[policy:_provider_litellm engine:l7]` | which policy entry decided, at which layer (`opa` = connection, `l7` = request) |
| `[reason:…]` | why it was refused |

Note the first line: `example.org` isn't in any rule, so the supervisor didn't even resolve it. DNS is part of the seal.

</Step>

</Section>

<Section n="2" title="Query the same events in Loki, across every sandbox">

The same events are shipped to Loki for every sandbox, so one LogQL query finds them across the whole cluster.

<Step n="1" title="Query the denials with LogQL">

The supervisors' logs are shipped to **Loki** by Alloy. The same events, for every sandbox, queryable with LogQL. Find the Loki service and ask for the denials of the last 15 minutes:

```bash
L=$(kubectl -n monitoring get svc loki -o jsonpath='{.spec.clusterIP}'); curl -sG "http://$L:3100/loki/api/v1/query_range" --data-urlencode 'query={namespace=~"lab|dev|team-.+", container="supervisor"} |= "OCSF" |= "DENIED"' --data-urlencode limit=10 | python3 -c 'import sys,json; [print(s["stream"]["pod"], v[1][:150]) for s in json.load(sys.stdin)["data"]["result"] for v in s["values"]]'
```

Each line carries the supervisor pod, so you know which sandbox it was. (The gateway also exports its OCSF events to Loki over OTLP, with the sandbox id as an attribute.)


</Step>

</Section>

<Section n="3" title="Explore the audit trail in Grafana">

Grafana puts a UI on the same Loki data: filter the denials, and watch new ones arrive live.

<Step n="1" title="Open Grafana's Explore on Loki">

Open Grafana from the site's **Links** page (`<your site>/grafana`, sign in with Keycloak as `demo`), go to **Explore**, pick **Loki**, and run:

```bash-ref
{namespace=~"lab|dev|team-.+", container="supervisor"} |= "OCSF" |= "DENIED"
```


</Step>

<Step n="2" title="Try other filters and go live">

Try `|= "HTTP:"` for every inspected request, or `|= "CONFIG:PUBLISHED"` to see each policy revision being loaded. Click **Live** and run the denied `curl` again: it appears within seconds.


</Step>

</Section>

<Section n="4" title="Follow agent traces in Tempo">

The supervisor also relays the agent's own **OpenTelemetry** spans: every sandbox process gets `OTEL_EXPORTER_OTLP_ENDPOINT` pointing at the supervisor, which tags each span with the sandbox id and forwards it to **Tempo**. An agent instrumented with OpenTelemetry (send `application/x-protobuf`) shows up in Grafana → Explore → **Tempo**, searchable by `resource.openshell.sandbox.id`. The gateway's own spans (every RPC, every sandbox create) are there too, under service `openshell-gateway`.

</Section>

<Callout type="nv" title="Why OCSF">
OCSF is a vendor-neutral schema that SIEMs (Splunk, Sentinel, Security Lake, …) already understand. The agent's network behaviour lands in the same security tooling as the rest of your estate, with no custom parser.
</Callout>

## What you learned

<Learned next="/learn/console" nextLabel="The OpenShell Console">

- **Every decision is an OCSF event** in the sandbox's log: what tried to connect, where, and whether the policy allowed it.
- **Loki has them for every sandbox**, so one LogQL query covers the whole cluster.
- **Grafana puts a UI on the same data**, with filters and a live tail.
- **The agent's own traces reach Tempo**, next to the gateway's.
