So far each agent had one tool, a shell, and the knowledge in its prompt. Real agents need more: **tools** that act on real systems, and **know-how** about how to use them. This module gives agents both, the way you'd run them for many teams on Kubernetes: through two open standards, with OpenShell deciding what each agent may use.

## Two standards

| | **MCP**, the Model Context Protocol | **Agent Skills** |
|---|---|---|
| What it is | A protocol: a client in the agent's harness calls **tools** on a server, over JSON-RPC. | A folder format: `SKILL.md` (a name, a description and instructions) plus optional scripts and references. |
| What it gives an agent | Actions and data: query Prometheus, list pods, scale a Deployment. | Know-how: which tool to use when, in what order, how to report. |
| Where it runs | The **server** runs outside the agent, here as a Deployment with its own Service account and RBAC. | **Inside** the agent's sandbox, as files in `~/.agents/skills/`, read by the harness. |
| Who supports it | Most harnesses: pi, Claude Code, Codex, Gemini CLI, Goose, OpenCode, … ([modelcontextprotocol.io](https://modelcontextprotocol.io/)) | Over forty clients, the same ones and more ([agentskills.io](https://agentskills.io/)) |

Both are **harness-neutral**: write the server or the skill once, and every agent on the cluster can use it. And neither needs trust in the agent: OpenShell's supervisor reads every MCP request and decides, per sandbox and per tool, whether it may go through.
