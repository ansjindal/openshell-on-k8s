## What you learned

- The fleet is four read-only pi specialists (logs, metrics, traces, events), each allowed only its own sre-tools MCP tools, plus an analyst with no tools at all.
- `fleet.txt` names each agent and its tools; `scripts/fleet.sh up` writes each policy, creates the sandbox, uploads pi, and adds the model, the MCP server, the platform skills and the role.
- The agents hold no credentials to Loki, Prometheus, Tempo or the Kubernetes API: the MCP server does, and each agent's policy decides which of its tools that agent may call.
- The orchestrator runs a fixed plan with one prescribed tool call per specialist, then hands all findings to the analyst for a root cause and a recommended action.
- In the incident lab you take `payments` down for real; the fleet diagnoses it from live telemetry and a human approves the fix.
- Extending the fleet is a few small, reviewable moves: a tool in the server, a line in `fleet.txt`, a role, a skill.
