The MCP server offers six tools to anyone who reaches it. Here you give an agent **four** of them: a sandbox whose policy reads every MCP request, allows the four read-only tools by name, and denies `scale_deployment`. Then pi, inside that sandbox, uses the tools, and tries the one it can't have.

## How OpenShell reads MCP

On an endpoint with **`protocol: mcp`**, the supervisor parses every request as MCP before it leaves the sandbox: the JSON-RPC **method** (`initialize`, `tools/list`, `tools/call`, …) and, for `tools/call`, the **tool name**. Rules allow or deny by method and tool; **deny rules win**. A refused call never reaches the server, and both outcomes are written as OCSF events.

Two limits to know: the tool's **arguments** are not inspected (an allowed tool may be called with any arguments the server accepts), and the server's **responses** are not parsed.

## What you learned

<Learned next="/learn/skill-repo" nextLabel="Share skills with every agent through git">

- **`protocol: mcp` makes the supervisor read MCP**: the method and the tool name of every request.
- **Allow by tool, deny by tool.** Deny rules win; a tool with no allow rule is refused too.
- **The decision is the platform's, not the agent's.** pi saw all six tools, but only four could be called, and each decision is an OCSF event.
- **Arguments and responses aren't inspected**: allow only tools whose every use is acceptable.

</Learned>
