Welcome to **OpenShell on Kubernetes**, a hands-on guide to running sandboxed AI agents on a real cluster. By the end you'll have created agents, opened and closed their network access line by line, given them credentials they never get to see, followed every decision in an audit trail, and pointed a small fleet of them at a live incident. All of it from a shell embedded in this page.

Everything runs on one VM that's already provisioned: **k3s** (single-node upstream Kubernetes), the **agent-sandbox** controller, the **OpenShell 0.1** gateway, **LiteLLM** in front of the model, **Keycloak** for sign-in, the **OpenShell Console**, and **Prometheus, Grafana, Loki and Tempo**. The default agent is **OpenClaw 🦞**.

## What you'll learn

- How the stack fits together, from `openshell sandbox create` to a pair of running pods.
- Why an agent's network is **deny by default**, and how to grant exactly one host, one method, one path.
- How an agent uses an API key it **never holds**: providers, profiles and credential placeholders.
- How to read the **audit trail** OpenShell writes for every allow and deny.
- How people sign in with **Keycloak** and what an admin, a user and a workspace can do.

## How the labs work

The course has **modules**, each played from one role: platform operator, agent developer, security reviewer, SRE. Lessons marked **LAB** are hands-on:

- Each lab is split into numbered **sections** (with a goal) and **steps**.
- A step's **RUN** panel shows the command; **Run ▷** executes it on your lab VM and streams the result into an **OUTPUT** panel. A successful run ticks the step off.
- The **OUTPUT** panel first shows what was recorded on a VM like yours, often with a **live diagram** of what the step adds. After Run it switches to your VM's output, and the diagram fills in with the names, states and ids your commands found. Names, ages and ids differ; the shape is what to compare.
- Each module opens with an **Overview** whose diagram builds as you scroll, and each lab ends with **What you learned**.
- **Cluster shell** (top right) opens a real bash shell on the VM, with `kubectl` and an `openshell` CLI already signed in as the lab operator. Use it to edit a command or keep a session; blocks marked **SHELL** open there automatically.
- Your progress (steps, lessons, quiz answers) is kept in this browser. **Clear outputs** in the sidebar wipes the run outputs.
- Each module ends with a **summary and knowledge check**.
