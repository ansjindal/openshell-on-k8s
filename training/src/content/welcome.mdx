Welcome to **OpenShell on Kubernetes**, a hands-on guide to running sandboxed AI agents on a real cluster. By the end you'll have created agents, opened and closed their network access line by line, given them credentials they never get to see, followed every decision in an audit trail, and pointed a small fleet of them at a live incident. All of it from a shell embedded in this page.

Everything runs on one VM that's already provisioned: **k3s** (single-node upstream Kubernetes), the **agent-sandbox** controller, the **OpenShell 0.1** gateway, **LiteLLM** in front of the model, **Keycloak** for sign-in, the **OpenShell Console**, and **Prometheus, Grafana, Loki and Tempo**. The default agent is **OpenClaw 🦞**.

## What you'll learn

- **What an AI agent is**: a model in a loop, a harness that runs its tools, and why that harness acting with your access is the problem.
- **How NVIDIA OpenShell puts a boundary outside the agent**: a gateway that governs, a supervisor that decides every connection, a policy file, and kernel filters that hold the agent in.
- Why an agent's network is **deny by default**, and how to grant exactly one host, one method, one path, one program.
- How an agent uses an API key it **never holds**: providers, profiles and credential placeholders.
- How to read the **audit trail** OpenShell writes for every allow and deny, and how people sign in with **Keycloak**, with roles and workspaces.
- How a small **fleet** of sealed agents finds the root cause of a real outage.

## How the course works

- **Module 0 is concepts**: what an agent is and how one poisoned input turns it against you. It uses animated scenes from the OpenShell talks: press **Next** in a scene (or click inside it and use →) to play each step, **Replay** to start again, **Full screen** for a bigger view.
- **Module 1 opens up OpenShell, chapter by chapter.** Each chapter explains one part with the scenes, then ends with an **exercise** you run on your VM: build and seal an agent, find a sandbox's two halves, test the seal from inside, open the network rule by rule, see a key the agent never holds, read its audit events, and verify the whole cluster.
- **Modules 2 to 4 are hands-on**, each played from one role: agent developer, security reviewer, SRE. Each opens with an **Overview** whose diagram builds as you scroll. Module 5 is where to go next.
- Lessons marked **LAB** are split into numbered **sections** (with a goal) and **steps**. A step's **RUN** panel shows the command; **Run ▷** executes it on your lab VM and the **OUTPUT** panel switches from the output recorded on a VM like yours to yours. Names, ages and ids differ; the shape is what to compare. A successful run ticks the step off.
- The **Cluster shell**, docked at the bottom of every page, is a real bash shell on the VM with `kubectl` and an `openshell` CLI already signed in as the lab operator. Drag its top edge to resize it, ▁ to minimize it. Blocks marked **SHELL** open there.
- Each lab ends with **What you learned**, and each module with a **summary and knowledge check**. Your progress is kept in this browser; **Clear outputs** in the sidebar wipes the run outputs.
