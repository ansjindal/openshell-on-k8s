Every decision the supervisor made in the last labs is on record. Generate a few denials from agent-0 and read the OCSF events its supervisor wrote.

**Concept:** [Part 10 in the Overview](/learn/openshell#t-10): signals and audit events.

<BeforeYouStart
  will="make agent-0 hit a few closed doors and read each decision as an OCSF event."
  time="about six minutes. Module 3 goes further, with Loki, Grafana and Tempo."
/>

<Section n="1" title="From the CLI" goal="Generate denials and read them in the sandbox's log.">

<Step n="1" title="Make some traffic">

Make some traffic first: one denied host and one denied admin call.

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -m 5 https://example.org >/dev/null; curl -s -X POST http://litellm.litellm.svc.cluster.local:4000/key/generate >/dev/null; echo done'
```


</Step>

<Step n="2" title="Read the OCSF events">

Now read the sandbox's log:

```bash
openshell logs agent-0 -n 200 --source sandbox --since 5m | grep OCSF
```
<Output>
<ExpectedOutput>
{`[sandbox] [OCSF ] [ocsf] NET:REFUSE [MED] DENIED example.org [reason:policy_dns_ineligible]
[sandbox] [OCSF ] [ocsf] NET:OPEN [MED] DENIED /usr/bin/curl(0) -> example.org:443 [reason:transparent_tcp_policy_denied]
[sandbox] [OCSF ] [ocsf] HTTP:POST [MED] DENIED POST http://litellm.litellm.svc.cluster.local:4000/key/generate [policy:_provider_litellm engine:l7] [reason:L7_REQUEST deny POST ...]`}
</ExpectedOutput>
</Output>

How to read a line:

| Part | Meaning |
|---|---|
| `NET:OPEN`, `NET:REFUSE`, `HTTP:POST`, `CONFIG:PUBLISHED`, `SSH:OPEN` | event class and activity: a connection, a refused DNS name, an HTTP request, a policy load, an exec session |
| `ALLOWED` / `DENIED` | the decision |
| `/usr/bin/curl(0) -> example.org:443` | which binary tried to reach what |
| `[policy:_provider_litellm engine:l7]` | which policy entry decided, at which layer (`opa` = connection, `l7` = request) |
| `[reason:…]` | why it was refused |

Note the first line: `example.org` isn't in any rule, so the supervisor didn't even resolve it. DNS is part of the seal.

</Step>

</Section>

## What you learned

<Learned next="/learn/os-check" nextLabel="Summary & knowledge check">

- **Every decision is an event**: allowed or denied, with the process, the destination, the rule and the reason.
- **The shorthand line reads left to right**: class, severity, action, process, destination, engine, reason.
- **The same events reach Loki**, so you can query every sandbox at once (Module 3).

</Learned>
