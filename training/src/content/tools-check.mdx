A quick look back at Module 3 before the capstone, where a fleet of agents uses these tools and skills.

## What you learned

- **MCP** moves tools out of the agent into a server: JSON-RPC over HTTP (`initialize`, `tools/list`, `tools/call`). On Kubernetes the server is a Deployment and Service with its own ServiceAccount and RBAC.
- An OpenShell endpoint with **`protocol: mcp`** reads every MCP request: rules allow or deny by method and tool name, deny rules win, and each decision is an OCSF event (`engine:l7-mcp`). Arguments and responses are not inspected.
- **Agent Skills** are folders with a `SKILL.md` (name, description, instructions). Harnesses read only names and descriptions at start, and the rest when a task matches.
- Skills belong in a **git repository** on the cluster: checked with `skill-lint`, pushed by the platform team, cloned read-only into each sandbox and linked into `~/.agents/skills`.
- The same MCP server and skills work for **pi and OpenClaw**, under the same policy; only each harness's program path goes into the rules.
