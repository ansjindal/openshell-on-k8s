The `litellm` provider was set up for you. Now build one yourself, for a service the agent should call with a token it never sees, and watch the real token arrive at the other end.

The service is a tiny **echo API** (`manifests/demo-echo/echo.yaml`): it answers every request with the method, path and headers it received. So you can see exactly what leaves the sandbox.


</Step>

<Section n="2" title="Write the profile" goal="Define where the token may go and for which requests.">

<Step n="1" title="Read the profile">

A **provider profile** is the contract for one kind of credential. Read `manifests/demo-echo/echo-api.profile.yaml`:

```bash
cat manifests/demo-echo/echo-api.profile.yaml
```

The parts that matter:

```bash-ref
credentials:
  - name: token
    env_vars: [ECHO_TOKEN]          # what the sandbox gets (as a placeholder)
    auth_style: bearer              # how the supervisor sends the real value
    header_name: authorization
endpoints:
  - host: echo.lab-demo.svc.cluster.local   # the ONLY place the token may go (FQDN)
    port: 8080
    protocol: rest
    enforcement: enforce
    rules:
      - allow: {method: GET, path: "/api/**"}   # and only for these requests
```

</Step>

<Step n="2" title="Lint and import it">

Lint it, then import it into the gateway:

```bash
openshell profile lint -f manifests/demo-echo/echo-api.profile.yaml && openshell profile import -f manifests/demo-echo/echo-api.profile.yaml
```

</Step>

<Section n="3" title="Create the provider" goal="Give the real token to the gateway, not the sandbox.">

<Step n="1" title="Create it from the environment">

A **provider** is an instance of a profile holding a real credential. Pass the value through the environment, so it never appears in your shell history or the process list:

```bash
ECHO_TOKEN=lab-secret-123 openshell provider create --name echo --type echo-api --credential ECHO_TOKEN
```
<Output>
<LiveDiagram id="providers" layer={3} />
<ExpectedOutput>
{`✓ Created provider echo`}
</ExpectedOutput>
</Output>

</Step>

</Section>

<Section n="4" title="Attach it to a running sandbox" goal="Add the credential and its policy to agent-0 live.">

<Step n="1" title="Attach the provider">

```bash
openshell sandbox provider attach agent-0 echo --wait
```
<Output>

  Installed: credentials=true, policy=true, future process environment=true

<Section n="5" title="Call the API" goal="See what actually arrives at the service.">

<Step n="1" title="A GET carries the real token">

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -H "Authorization: Bearer $ECHO_TOKEN" http://echo.lab-demo.svc.cluster.local:8080/api/whoami' | grep -E '"path"|authorization'
```
<Output>
<LiveDiagram id="providers" layer={6} />
<ExpectedOutput>
{`  "path": "/api/whoami",
    "authorization": "Bearer lab-secret-123"`}
</ExpectedOutput>
</Output>

The agent sent the placeholder; the echo service received `lab-secret-123`. The supervisor swapped it on the way, because the request matched the profile's endpoint and rule.

</Step>

<Step n="2" title="A POST never leaves">

A `POST` doesn't match, so it never leaves:

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -o /dev/null -w "HTTP %{http_code}\n" -X POST -H "Authorization: Bearer $ECHO_TOKEN" http://echo.lab-demo.svc.cluster.local:8080/api/x'
```
<Output>
<LiveDiagram id="providers" layer={7} />
<ExpectedOutput>
{`HTTP 403`}
</ExpectedOutput>
</Output>

</Step>

</Section>

<Section n="6" title="Rotate the token" goal="Change the credential without touching the sandbox.">

<Step n="1" title="Update the provider">

Change the credential in the gateway; every sandbox with the provider attached picks it up, still without a restart:

```bash
ECHO_TOKEN=lab-secret-456 openshell provider update echo --credential ECHO_TOKEN --wait
```

<LiveDiagram id="providers" layer={8} />

</Step>

<Step n="2" title="See the new value arrive">

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -H "Authorization: Bearer $ECHO_TOKEN" http://echo.lab-demo.svc.cluster.local:8080/api/whoami' | grep authorization
```
<Output>
<LiveDiagram id="providers" layer={9} />
<ExpectedOutput>
{`    "authorization": "Bearer lab-secret-456"`}
</ExpectedOutput>
</Output>

The agent's placeholder didn't change; only the value behind it did.

</Step>

</Section>

<Section n="7" title="Detach it" goal="Revoke the credential and its policy.">

<Step n="1" title="Detach the provider">

Detaching revokes both the credential and the policy entry the profile added:

```bash
openshell sandbox provider detach agent-0 echo --wait
```

<LiveDiagram id="providers" layer={10} />

</Step>

</Section>

<Callout type="nv" title="Why this matters">
An agent with a token in its environment can send it anywhere: in a URL, a log line, a prompt-injected request to an attacker. With a provider, the token is only ever materialised by the supervisor, on requests that match the profile's endpoint and rules, and the agent can't read it back. Rotation and revocation are one command, for every sandbox at once.
</Callout>
