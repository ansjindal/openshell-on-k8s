Now create an agent. A sandbox is the unit of work: one command, and the gateway puts a fully isolated agent environment on the cluster.

## The easy way: the fleet helper

`./scripts/fleet` is a thin wrapper around the `openshell` CLI and `kubectl` that the next lessons reach for:

```bash-ref
fleet up [N]                          # create sandboxes agent-0 … agent-(N-1)
fleet down                            # delete every fleet sandbox
fleet status                          # sandboxes + the pods behind them
fleet task "<prompt>" [agent-i|all]   # run a prompt across the fleet, in parallel
fleet shell <agent-i>                 # interactive shell inside one sandbox
fleet logs <agent-i>                  # OpenShell logs for one sandbox
```

Bring the fleet to two:

```bash
./scripts/fleet up 2
```

## The direct way: the openshell CLI

`fleet up` runs this for each agent:

```bash-ref
openshell sandbox create --name agent-1 \
  --provider litellm \
  --policy manifests/policies/baseline.yaml \
  --memory 3Gi \
  --no-tty --detach -- sleep infinity
```

| Flag | What it does |
|---|---|
| `--provider litellm` | attach model access: a placeholder `LITELLM_API_KEY`, plus the provider's policy entry |
| `--policy …baseline.yaml` | start from the lab baseline: deny all network, `/sandbox` and `/tmp` writable |
| `--memory 3Gi` | the workload pod's memory request and limit (one OpenClaw turn peaks near 2 GB). `--cpu` would also become a *request*: on an 8-vCPU VM a few of those fill the node |
| `--detach` and `-- sleep infinity` | the command after `--` is the sandbox's **main process**; the sandbox lives as long as it runs |
| (no `--from`) | the gateway's default image, `ghcr.io/ansjindal/openclaw-sandbox`: OpenClaw on the OpenShell community base |

Without a trailing command and `--detach`, `openshell sandbox create` opens an interactive shell in the new sandbox instead; type `exit` to leave.

## What happened on the cluster

The CLI never touches Kubernetes. It calls the **gateway**, which:

1. stores the sandbox and its policy (revision 1);
2. writes a `Sandbox` resource; the **agent-sandbox controller** turns it into the **workload pod** `default--agent-1` (workspace `default`);
3. starts the **supervisor pod** `os-supervisor-<id>`, which fetches the policy and the provider credentials and becomes the workload's only network path.

```bash
kubectl -n openshell-sandboxes get sandboxes
```
<ExpectedOutput>
{`NAME               READY   REASON              AGE
default--agent-0   True    DependenciesReady   27m

</ExpectedOutput>

Each pod is labelled with its role and its pair:

```bash
kubectl -n openshell-sandboxes get pods -L openshell.ai/boundary-role,openshell.ai/boundary-pair
```

`openshell sandbox get agent-1` shows the same sandbox from the gateway's side: its id, image, phase and attached providers.

<Callout type="note" title="Keep agent-0 around">
The rest of the course, including the console and the Part III capstone, assumes <code>agent-0</code> is up. To scale back without tearing everything down: <code>openshell sandbox delete agent-1</code>. <code>fleet down</code> is for when you're done with the launchable.
</Callout>
