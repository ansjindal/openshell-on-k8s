**Traces** show where time goes, **gateway metrics** show saturation, and **OCSF events** record every security decision. Supervisors export directly; the agent's own spans go to a relay the supervisor provides, with no egress rule needed. Join everything on `openshell.sandbox.id`.

</Section>

<Section n="2" title="Reading an OCSF event">

<DeckScene src="openshell" only="ocsf" title="Reading an OCSF event" />

A shorthand line such as

```text
OCSF NET:OPEN [MED] DENIED /usr/bin/curl(64) -> httpbin.org:443 [policy:- engine:opa] [reason:no matching policy]
```

reads left to right: the event class (`NET:OPEN`, network activity), the severity, the action, the process and destination, which engine and rule decided, and why. The same event is also a JSONL record and an OTLP log record, so any SIEM that speaks OCSF can read it.

</Section>

## Exercise: read the events

Generate a few denials from agent-0 and read the OCSF events its supervisor wrote.

<Section n="3" title="From the CLI" goal="Generate denials and read them in the sandbox's log.">

<Step n="1" title="Make some traffic">

Make some traffic first: one denied host and one denied admin call.

```bash
openshell sandbox exec -n agent-0 -- sh -c 'curl -s -m 5 https://example.org >/dev/null; curl -s -X POST http://litellm.litellm.svc.cluster.local:4000/key/generate >/dev/null; echo done'
```


</Step>

<Step n="2" title="Read the OCSF events">

Now read the sandbox's log:

```bash
openshell logs agent-0 -n 200 --source sandbox --since 5m | grep OCSF
```
<Output>
<ExpectedOutput>
{`[sandbox] [OCSF ] [ocsf] NET:REFUSE [MED] DENIED example.org [reason:policy_dns_ineligible]
[sandbox] [OCSF ] [ocsf] NET:OPEN [MED] DENIED /usr/bin/curl(0) -> example.org:443 [reason:transparent_tcp_policy_denied]
[sandbox] [OCSF ] [ocsf] HTTP:POST [MED] DENIED POST http://litellm.litellm.svc.cluster.local:4000/key/generate [policy:_provider_litellm engine:l7] [reason:L7_REQUEST deny POST ...]`}
</ExpectedOutput>
</Output>

How to read a line:

| Part | Meaning |
|---|---|
| `NET:OPEN`, `NET:REFUSE`, `HTTP:POST`, `CONFIG:PUBLISHED`, `SSH:OPEN` | event class and activity: a connection, a refused DNS name, an HTTP request, a policy load, an exec session |
| `ALLOWED` / `DENIED` | the decision |
| `/usr/bin/curl(0) -> example.org:443` | which binary tried to reach what |
| `[policy:_provider_litellm engine:l7]` | which policy entry decided, at which layer (`opa` = connection, `l7` = request) |
| `[reason:…]` | why it was refused |

Note the first line: `example.org` isn't in any rule, so the supervisor didn't even resolve it. DNS is part of the seal.

</Step>

</Section>

## What you learned

<Learned next="/learn/big-picture" nextLabel="OpenShell on Kubernetes: this lab">

- **Three signals**: traces, metrics, OCSF events, joined on the sandbox ID.
- **Every decision is an event**: allowed or denied, with the process, the destination and the rule.
- **Vendor-neutral**: OCSF lands in the security tooling you already run.

</Learned>
